# Lab 06 · 正确地评估推理模型

评估比训练更容易做错。

```bash
make lab06 ARGS="--n 200 --k 8"
make lab06 ARGS="--n 200 --k 8 --compare Qwen/Qwen2.5-0.5B-Instruct outputs/lab01_sft outputs/lab04_grpo/final"
```

## 四个指标，测的是不同的东西

| 指标 | 定义 | 用途 |
|:---|:---|:---|
| greedy / pass@1 | temp=0 采一次 | ❌ **推理模型不要用**：一个 token 走错就全错，方差极大；很多推理模型 temp=0 下会复读 |
| **avg@k** | 采 k 次求平均正确率 | ✅ 报告推理模型的标准做法 |
| **pass@k** | 采 k 次至少对一次 | 衡量「能力边界」 |
| maj@k | 采 k 次多数投票 | 衡量「自洽性」 |

### pass@k 必须用无偏估计

直接「采 k 次看有没有对的」是**有偏且高方差**的。正确做法（Codex 论文）：

```
pass@k = E[ 1 − C(n−c, k) / C(n, k) ]
```

每题采 n 个样本（建议 n ≥ 4k），其中 c 个正确。代码里用连乘形式避免大数溢出。

## 必须报标准误

AIME 只有 30 题，一题 = 3.3 分。脚本会输出 `avg@k_stderr`：

```
avg@8         = 0.5480
avg@8_stderr  = 0.0351
```

**两个模型的差距小于 2 倍标准误，就不能说谁更好。** 这是最常被忽略的一点。

## 怎么读对比结果

- **pass@1 vs pass@k 差距大** = 模型「偶尔能做对但不稳定」。RL 的主要作用就是把 pass@k 转成 pass@1。
- **maj@k 明显高于 avg@k** = 错误是随机分布的（投票能纠正）；两者接近 = 错误是系统性的（投票救不了）。
- **format_rate < 0.9** = 格式没学稳，RL 的格式奖励还没饱和。

## 污染检查

脚本会用 13-gram 匹配估计测试题与训练题的重叠率。

⚠️ 但这**只能查你自己的训练集**。GSM8K/MATH 很可能已经在模型的预训练语料里，
这个你查不到。严肃评测请用**训练截止之后**的题目：AIME 2025、LiveCodeBench 最新分片、HMMT。

## 五个常见评估错误

1. 只报一个数，不报标准误
2. 用不同的解码参数比较（你 temp=0.6，baseline temp=0）
3. 用不同的 prompt 模板比较（模板影响常常比算法改进还大）
4. 忽略污染
5. 只看目标领域 —— 数学 RL 之后一定要查 MMLU/IFEval 有没有退化。**RL 会牺牲你没有奖励的一切。**
