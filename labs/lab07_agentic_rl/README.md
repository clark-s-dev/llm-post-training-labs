```bash
make lab07 ARGS="--steps 100"
make lab07 ARGS="--steps 30 --no-mask"     # 错误示范，看失败模式
```

## 交互格式

```
<think>需要算 15 乘以 4</think>
<tool>15*4</tool>
<result>60</result>          ← 环境返回，必须 mask
<think>所以答案是 60</think>
\boxed{60}
```

## ★★ 本 lab 最重要的一件事：loss mask ★★

工具返回的 token **不是模型的动作**，是环境的输出。不屏蔽它们会怎样：

1. 策略梯度会去提高「生成工具返回内容」的概率 → 模型开始复读计算结果
2. 更糟：这些 token 的重要性比率 `ρ` 完全没有意义（分母是随机的 ——
   模型从没打算生成它们），会出现 10^±5 这种值 → **梯度爆炸**

如果工具返回占了轨迹的 60%，那你 60% 的梯度都是垃圾。

```python
token_ids += obs_ids
# ★★★ 整个 Agentic RL 最关键的一行 ★★★
loss_mask += [0 if cfg.mask_tool_output else 1] * len(obs_ids)
```

```bash
make lab07 ARGS="--steps 30 --no-mask"
```

## 多轮场景变了什么

| | 单轮 RLVR | Agentic RL |
|:---|:---|:---|
| 转移 | 确定性（字符串拼接） | **随机**（工具返回不由模型决定） |
| 哪些 token 该学 | 全部 completion | **只有模型生成的** |
| 轨迹长度方差 | 中等 | **可达 100 倍**（1 轮 vs 41 轮） |

注意：转移变随机了，但第 04 章「环境项在梯度中消失」的结论**依然成立** ——
`log P(o|a)` 不含 θ，求导仍为 0。变化的是方差。

## 工具沙箱：绝不能用 eval()

RL 训练会跑**几百万次**模型生成的字符串。模型不需要有恶意，
它只要碰巧生成了 `__import__('os').system('rm -rf /')`，你的机器就完了。

`safe_calc()` 用 AST 白名单，只放行数字和四则运算。还有一个容易漏的点：

```python
# ★ 幂运算必须在计算之前限制指数。Python 大整数是任意精度的，
#   9**9**9 会先算出一个 3.7 亿位的数 —— 进程直接卡死，整个训练挂掉。
if isinstance(n.op, ast.Pow) and (abs(b) > MAX_EXP or abs(a) > 1e6):
    raise ValueError("指数过大")
```

这不是理论风险 —— 开发本 lab 时就真的撞上了。`make test` 里有对应的回归测试。

## 奖励设计

- 主奖励：最终答案对不对
- 门控：工具调用格式必须合法
- 轻微效率惩罚：防止模型学会「反复调工具拖时间」
- **❌ 不给「调用了工具」本身发奖励** —— 什么时候该调，正是我们想让 RL 学的。
  直接奖励调用会让模型对 `1+1` 也去调计算器。

## 该看什么

| 指标 | 健康值 | 异常含义 |
|:---|:---|:---|
| `可学token` | 20%~50% | < 10% 工具返回太长；≈ 100% mask 没生效 |
| `ratio_max` | < 5 | 飙升 = mask 有问题 |
| `用工具` | 稳步上升 | 一直 0 = 模型没学会格式，先做 SFT |
| `工具报错` | 下降 | 不降 = 模型没学会从错误中恢复 |
| `轮数` | 1~3 | 一路涨 = 效率惩罚不够 |
