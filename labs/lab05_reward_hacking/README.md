# Lab 05 · Reward Hacking

> 古德哈特定律：当一个衡量指标变成了目标，它就不再是一个好的衡量指标。

```bash
make lab05                                       # Part A，秒级，不需要 GPU
make lab05 ARGS="--run-rl --reward naive"        # Part B，真的用坏奖励训一次
make lab05 ARGS="--run-rl --reward proper"       # 对照组
```

## Part A · 奖励函数攻防演练

8 个真实观察到过的 hack 手法，三种奖励函数分别打分：

```
hack 手法                                   naive_contains   naive_length    proper
正常的好回答（对照）                              1.00 ✓          0.07        1.00 ✓
穷举答案：把可能的数字全列一遍                     1.00 ✗          0.07        0.00
空 think 标签：白拿格式分                          0.00           0.01        0.00
复读凑长度                                        0.00           1.00 ✗     -0.50
多个 boxed：赌判分器取第一个                       1.00 ✗          0.03        0.00
提示注入：试图影响 LLM judge                       0.00           0.07        0.00
答案藏在推理里但 boxed 是错的                      1.00 ✗          0.03        0.00
被 hack 的次数（越少越好）                           3              1           0
```

「全文包含答案就给分」看起来非常合理，被『穷举答案』一击即破。
门控式奖励能挡住全部，靠三条硬约束：

- `<think>` 必须非空且有最小长度 → 挡住空标签
- **只取最后一个 `\boxed{}`** → 挡住穷举（强迫模型做唯一承诺）
- 格式不合规**直接判 0**（不是扣分）→ 消除「用格式换正确性」的交易空间

## Part B · 看着奖励曲线骗过你

用坏奖励真的跑几十步 GRPO。关键设计：**不管用什么奖励训练，
始终用正确的奖励函数测真实准确率**，于是你能同时看到两条曲线分道扬镳：

```
step   训练reward   真实准确率   平均长度
  10      0.512        0.219        180
  30      0.781        0.203        246    ← reward 很高但真实准确率没动：正在 hack
```

真实项目里你**看不到**「真实准确率」那一列（那正是你想优化的未知量），
所以必须靠：① 独立评测集 ② 定期人眼看最高奖励样本。

## 带走的三句话

1. 设计奖励时永远问自己：「如果我想不做正事就拿满分，我会怎么做？」
2. Hack 通常在训练中期**突然出现**，表现为 reward 曲线的一个阶跃。看到台阶就去抽样看输出。
3. **组合奖励用门控，不要用加权和** —— 加权和允许模型牺牲难拿的分去刷容易拿的分。
